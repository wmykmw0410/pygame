# 画像を描く

## ステップ1.画像を読み込む
```python
"""image.load関数を使う
読み込む画像がどこにあるか(画像ファイルパス)を指定する
このコースでは pygame フォルダ(リポジトリのルート)を作業ディレクトリとして実行するため、
「04_draw_imagesフォルダの中のimagesフォルダの中のcar.pngファイル」であれば、
「pg.image.load("04_draw_images/images/car.png")」と指定し、画像用の変数に代入する"""
画像変数 = pg.image.load("画像ファイルパス")
```

- 読み込みは、ゲームの準備（`while True:` の前）で1回だけ行う。ループの中で毎回読み込むと、毎フレームファイルを読むことになり重くなる
- `FileNotFoundError: No file '...' found in working directory '...'` と出たら、パスの書き間違いか、実行しているフォルダ（作業ディレクトリ）が違う。`pwd` でリポジトリのルートにいるか確認する（→ [03_linux_command](../03_linux_command/README.md)）
- 透明な部分のある PNG は、`.convert_alpha()` を付けて読み込む書き方もある（[16_battle_game](../16_battle_game/README.md) で出てくる）。この章では付けなくても表示できる

## ステップ2.読み込んだ画像を描画する
```python
"""screenのblit関数を使って描画する
読み込んだ画像データを入れた変数と表示する位置(x,y)を指定する"""
screen.blit(画像変数, (x, y))
```

`(x, y)` は画像の**左上**の位置になる。後から `blit` した画像は、先に描いた画像の上に重なる。

サンプル: [example/ex01.py](example/ex01.py)

練習: [practice/practice01.py](practice/practice01.py)（「# ★」の部分が空欄になっているので、サンプルを見ながら自分の手でコードを打ち込んで完成させよう）

動いたら、数字を書き換えてもう一度動かし、変化を確認する。

| 変えるもの | 確認すること |
| --- | --- |
| 描画する位置 `(100, 100)` → `(400, 300)` | 画像が移動する（`(x, y)` は画像の左上） |
| `(0, 0)` や `(750, 550)` | 画面の端では、はみ出した部分は表示されない |
| 同じ画像を少しずらして2回 `blit` | 後から描いた方が上に重なる。2行の順番を入れ替えると重なり方が逆になる |

## ステップ3.画像のサイズを変更する
```python
"""「画像を読み込む」後に実行する
「画像のサイズを変更する」にはtransform.scale関数を使って、
画像を入れた変数、幅、高さを指定し、変数に入れ直す"""
画像変数 = pg.transform.scale(画像変数, (幅, 高さ))
```

| 項目 | 内容 |
| --- | --- |
| デフォルトサイズ | `image.load()` で読み込んだ画像の元のサイズ(変更なし) |
| 元のサイズを確認 | `画像変数.get_size()` → `(幅, 高さ)` のタプルで返る |
| 幅・高さの範囲 | 1以上の整数(ピクセル単位) |

`scale` は縦横の比率を気にせず、指定したサイズに引き伸ばす。元と違う比率にすると画像が歪むので、`get_size()` で元のサイズを確認して比率をそろえるとよい。

サンプル: [example/ex02.py](example/ex02.py)

練習: [practice/practice02.py](practice/practice02.py)

| 変えるもの | 確認すること |
| --- | --- |
| `(50, 50)` → `(200, 200)` / `(10, 10)` | 指定したサイズで大きく・小さく表示される |
| `(200, 50)` / `(50, 200)` | 縦横の比率が変わると、画像が横長・縦長に歪む |
| `(150, 150)` | 元のサイズ `(100, 100)` と同じ比率なので、歪まずに大きくなる |

## 画像はRectとして扱える

### Rectとは
`Surface`（`pg.image.load()` で読み込んだ画像）は、**絵のデータしか持っていない**。画面のどこに置くかという位置の情報は持っていない。
そこで、位置と大きさをひとまとめにして管理するのが **Rect**（`x座標, y座標, 幅, 高さ`）。

| 持っているもの | 役割 |
| --- | --- |
| 画像（Surface） | 絵そのもの |
| Rect | その絵の位置と大きさ（動かす・衝突を調べるときに使う） |

ゲームでは「画像」と「Rect」を1組で持ち、Rectの位置を変えて画像を動かす。

### 画像からRectを取得する
```python
"""画像からRectを取得することで、位置管理や衝突判定に使える
get_rect()で画像と同じサイズのRectを取得する"""
myrect = 画像変数.get_rect()
```

サイズは画像と同じになる。位置は何も指定しなければ左上が `(0, 0)` になる。

```python
# 例: 50×50に縮小した画像
myrect = 画像変数.get_rect()
print(myrect)   # <rect(0, 0, 50, 50)>  → (x, y, 幅, 高さ)
```

位置は取得するときに指定できる。

```python
# 左上の位置を指定してRectを取得する
myrect = 画像変数.get_rect(topleft=(100, 100))   # <rect(100, 100, 50, 50)>

# 中心の位置を指定してRectを取得する
myrect = 画像変数.get_rect(center=(400, 300))    # <rect(375, 275, 50, 50)>
```

`center=(400, 300)` なら、画像の中心が `(400, 300)` に来るように左上の位置が自動で計算される（サイズが違う画像でも、中心をそろえて置きたいときに便利）。

### Rectの値を使う
Rectの値は、変数に `.`（ドット）をつけて読み書きできる。

| 属性 | 意味 |
| --- | --- |
| `myrect.x` / `myrect.y` | 左上のx,y座標 |
| `myrect.width` / `myrect.height` | 幅 / 高さ |
| `myrect.topleft` | 左上 (x, y) |
| `myrect.center` | 中心 (x, y) |
| `myrect.right` | 右端のx座標（`x + width`） |
| `myrect.bottom` | 下端のy座標（`y + height`） |

`(x, y)` が基準にしているのは**左上隅**。中心や右端・下端を基準にしたい場合の考え方は [02_draw_shapes の「基準点」](../02_draw_shapes/README.md#基準点) を参照。

### Rectを使って描画する・動かす
```python
# blitの第2引数にRectをそのまま渡せる（Rectの左上の位置に描画される）
screen.blit(画像変数, myrect)

# Rectの値を変えると、描画される位置が変わる
myrect.x += 1   # 右に1ピクセル動く
```

`screen.blit(画像変数, (x, y))` と違い、位置を数字で直接書かなくてよい。ループの中で毎回 `myrect.x` を増やしてから `blit` すれば、画像が少しずつ動いて見える。

### Rectは衝突判定にも使える
Rectには、重なっているかを調べる機能がある。ゲームで「弾が敵に当たったか」「ボタンがクリックされたか」を調べるときに使う。

```python
# 2つのRectが重なっているか(True / False)
myrect.colliderect(other_rect)

# 点(x, y)がRectの中に入っているか(True / False)
myrect.collidepoint(x, y)
```

使い方の詳細はこの後の章で学ぶ（例: [05_event_process](../05_event_process/README.md) のボタン）。

サンプル: [example/ex03.py](example/ex03.py)（Rectの `x` を増やして、画像を横に動かす）

練習: [practice/practice03.py](practice/practice03.py)

| 変えるもの | 確認すること |
| --- | --- |
| `myrect.x += 1` の `1` → `5` / `-1` | 数が大きいほど速く動く。マイナスにすると逆向き（左）に動く |
| `myrect.y += 1` を追加 | `x` と `y` が両方変わるので、斜めに動く |
| `topleft=(100, 100)` → `(0, 400)` | 動き始める位置が変わる |
| `topleft=(100, 100)` → `center=(400, 300)` | 画像の中心が `(400, 300)` に来る位置から動き始める |
| `FPS = 60` → `10` | 1秒あたりの描画回数が減り、動きがカクカクして見える |
