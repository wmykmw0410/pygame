## 2進数

コンピュータは、内部的にすべての情報を `0` と `1` だけ（2進数）で扱っている。

```python
bin(10)          # → '0b1010'（10進数の10は、2進数だと1010）
int("1010", 2)   # → 10（2進数の文字列を10進数の整数に変換）

10 & 6      # ビット単位のAND（2進数どうしの演算）
10 | 6      # ビット単位のOR
```

| 10進数 | 2進数 |
| --- | --- |
| 0 | 0 |
| 1 | 1 |
| 2 | 10 |
| 3 | 11 |
| 4 | 100 |
| 8 | 1000 |

> 普段の Python コードで2進数を直接扱う場面は少ないが、「コンピュータの中では最終的に0と1で表現されている」と知っておくと、真偽値（`True`/`False`）が実質的に `1`/`0` として扱われる（`True + True` は `2` になる）ことにも納得しやすくなる。

## 浮動小数点数の誤差

小数（`float`）は、2進数で正確に表現できない値がある。そのため、直感に反する結果になることがある。

```python
0.1 + 0.2          # → 0.30000000000000004（0.3 にならない！）
0.1 + 0.2 == 0.3   # → False
```

これは Python のバグではなく、**2進数で0.1という値を正確に表現できない**ことによる、浮動小数点数という仕組み共通の性質。

```python
# 対策1: 誤差を許容して比較する
abs((0.1 + 0.2) - 0.3) < 1e-9   # → True

# 対策2: round() で丸めてから比較する
round(0.1 + 0.2, 5) == round(0.3, 5)   # → True
```

> HPやスコアのような「整数で十分な値」は `int` を使い、`float` はどうしても小数が必要なとき（移動速度など）に限定して使うと、この種の誤差に悩まされにくい。

## メモリとミュータビリティ

[タプル](../docs/python_grammar/01_basic.md#immutableイミュータブルと-mutableミュータブル)で扱った immutable/mutable の違いは、実は「値がメモリ上でどう扱われるか」という話でもある。

```python
a = [1, 2, 3]
b = a            # b は a と同じリストを指している（コピーではない）
b.append(4)
print(a)         # → [1, 2, 3, 4]（a も変わってしまう！）

c = a.copy()     # 別のリストとしてコピーする
c.append(5)
print(a)         # → [1, 2, 3, 4]（c を変えても a は変わらない）
```

リストのような mutable なオブジェクトは、変数に代入したときに「値そのもの」ではなく「値が置かれている場所（参照）」がコピーされる。そのため、`b = a` のあとに `b` を変更すると `a` も変わって見える。immutable な `int`/`str`/`tuple` ではこの問題は起きない（変更するたびに新しい値が作られるため）。

> 「意図せず元のリストまで変わってしまった」というバグに出会ったら、この仕組みを思い出すとよい。
