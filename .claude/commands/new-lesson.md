依頼内容: $ARGUMENTS

新しいレッスンを追加して。次の手順で進める。

## 1. 番号を決める

リポジトリ直下の `[0-9][0-9]_*` フォルダを一覧し、既存の最大番号 + 1 を新しいレッスン番号にする（番号は2桁でゼロ埋めする。例: 9 → `09`、35 → `35`）。`$ARGUMENTS` に番号やフォルダ名が明示されていればそれを優先する。

## 2. レッスンの形式を確認する

`$ARGUMENTS` だけで判断できない場合は、AskUserQuestion で確認してから作業を始める。

- **ステップ形式**（16_battle_game, 21_super_mario のような、1本のゲームを `README.md` の「ステップ1」「ステップ2」…で組み立てるもの）
- **サンプル羅列形式**（05_event_process, 09_actiongame, 20_sprite のような、複数の `example/exNN.py` を並べて概念ごとに解説するもの）

あわせて、テーマ（何を学ぶレッスンか）と、画像・音声素材が必要かどうかを確認する。

## 3. フォルダ構成を作る

**ステップ形式の場合**

```
NN_<名前>/
  main.py            # まずは pg.init() とウィンドウ表示だけの最小スタブ
  game/
    __init__.py       # 空、または最初に作るクラスをエクスポート
  images/             # 画像が必要な場合
```

**サンプル羅列形式の場合**

```
NN_<名前>/
  example/
    ex01.py           # 最初のサンプルのスタブ
```

いずれの形式でも `README.md` を作成し、最低限次のセクションを用意する（プレースホルダーで構わないが、後で `/verify-lesson` に通せる形にしておく）。

- 目次（見出しと対応するアンカーリンク）
- ゲームを体験する / ファイル構成（ステップ形式の場合）
- 設計の全体像（複数クラスが絡む場合）
- ステップ1、またはサンプルの最初のセクション

## 4. CLAUDE.md の規約に従う

- 定数は共通の `config.py` にまとめず、使うファイルの先頭にローカルに書く。
- カプセル化のための `_` 接頭辞は使わない。
- 画像を新しく作る必要がある場合、実在ゲームの模写にせず、ジャンルのお約束を踏まえたオリジナル素材にする。複雑なドット絵が要るなら `_generate_assets.py` + `*_pixels.txt`（1文字 = 1ピクセルの文字グリッド、`x` = 透明）のパターンを使う（20, 23 を参照）。

## 5. ルートの README.md を更新する

- 「進捗」チェックリストに新しいレッスンの行を追加する（サブ項目は空でよい）。
- 下部の索引テーブル（フォルダ | テーマ | 概要 | リンク）に新しい行を追加し、対応するセクション（準備 / pygame 入門 / ゲーム制作 / Python 応用 / 発展）に振り分ける。まだ実装途中なら「概要」欄にその旨を書き、リンクは `—` にする。完成後は必ずこの行を更新する（CLAUDE.md 参照）。

## 6. 検証する

作成し終えたら `/verify-lesson NN_<名前>` を実行し、コンパイル・スモークテスト・README/ソース整合性・アンカーを確認してから完了を報告する。
