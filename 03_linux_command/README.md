- **ターミナル**: コマンドを入力するローカルの画面(自分のPC上で動く)

| CUI (Character User Interface) | 文字だけの画面 | キーボードのみ |
| GUI (Graphical User Interface) | 視覚的な画面 | マウス・タッチ操作 |

# 1. パスの理解

パスとは、ファイルやディレクトリの場所を表す文字列のこと

## 絶対パスと相対パス

| 種類 | 基準 | 例 |
| --- | --- | --- |
| 絶対パス | ルートディレクトリ `/` から始まる | `/home/user/projects/game.py` |
| 相対パス | 今いるディレクトリ(カレントディレクトリ)から始まる | `./projects/game.py` |

## 特別なディレクトリ記号

| 記号 | 意味 |
| --- | --- |
| `.` | カレントディレクトリ(今いる場所) |
| `..` | 親ディレクトリ(1つ上の階層) |
| `~` | ホームディレクトリ |
| `/` | ルートディレクトリ(最上位) |

## ディレクトリのツリー構造

```
/                        ← ルートディレクトリ
└── home/
    └── user/            ← ホームディレクトリ (~)
        └── projects/    ← カレントディレクトリ (.) とする
            ├── game.py
            └── images/
```

`projects/` にいるとき
- `./game.py` = `game.py`(カレントディレクトリのgame.py)
- `../` = `user/`(1つ上)
- `/home/user/projects/game.py` = 絶対パスで同じファイルを指す

# コマンドでのディレクトリ操作

## 現在地を確認する

```bash
pwd
# Print Working Directory: 今いるディレクトリの絶対パスを表示
```

## ディレクトリの中身を見る

```bash
ls
# list: ファイルやディレクトリの一覧を表示

ls -l   # 詳細表示(Long)
ls -a   # 隠しファイルも表示(all)
```

## ディレクトリを移動する

```bash
cd ディレクトリ名   # change directory: 指定したディレクトリへ移動
cd ..              # 1つ上の階層へ移動
cd ~               # ホームディレクトリへ移動
cd -               # 直前にいたディレクトリへ移動
```

練習: [practice/practice01.md](practice/practice01.md)（「★」の部分が空欄になっているので、README を見ながら自分の手でコマンドを打ち込んで完成させよう）

打ち込んだら、コマンドを変えて試し、変化を確認する。

| 試すこと | 確認すること |
| --- | --- |
| `ls` → `ls -l` → `ls -a` | `ls -l` は1行ずつ詳しく表示する（行の先頭が `d` ならディレクトリ、`-` ならファイル）。`ls -a` は `.` で始まる隠しファイルや、`.`・`..` も表示する |
| `cd ..` を2回 | そのたびに1つ上の階層に移動し、`pwd` の表示が変わる |
| `cd /` → `pwd`・`ls` | ルートディレクトリ（`/`、最上位）に移動する。`ls` でシステムのフォルダが並ぶ（見るだけで、変更はしない） |
| `/` にいる状態で `cd ..` | これ以上は上がれないので、`/` のまま |
| `cd ~` → `cd /` → `cd -` | 直前にいた場所（ホームディレクトリ）に戻る（移動した先のパスも表示される） |
| 存在しない名前に `cd`（例: `cd abc`） | `No such file or directory` などのエラーが出て、その場にとどまる（現在地は変わらない） |

## ディレクトリを作成・削除する

```bash
mkdir ディレクトリ名          # make directory: ディレクトリを作成
mkdir -p 親/子/孫             # 上位ディレクトリも含めて一括作成

rmdir ディレクトリ名          # remove directory: 空のディレクトリを削除
rm -r ディレクトリ名          # ディレクトリと中身ごと削除
```

## ファイルを操作する

```bash
touch ファイル名              # 空のファイルを作成

rm ファイル名                 # ファイルを削除
rm -i ファイル名              # 削除前に確認する

cp コピー元 コピー先          # ファイルをコピー
mv 移動元 移動先              # ファイルを移動(ファイル名の変更にも使える)
```

`rm` で消したファイルは、ゴミ箱には入らず、元に戻せない。消す前に、本当に消してよいものか確認する。

練習: [practice/practice02.md](practice/practice02.md)（練習用の「Practice」フォルダの中だけで試す）

| 試すこと | 確認すること |
| --- | --- |
| `mkdir x/y/z`（`-p` なし） | `x` が無いのでエラーになる。`-p` を付けると、`x`・`y`・`z` が一括で作られる |
| すでにある名前で、もう一度 `mkdir` | エラーになる（`File exists`）。ただし `mkdir -p` なら、すでにあってもエラーにならない |
| 中身のあるフォルダに `rmdir` | エラーになる（`Directory not empty`）。空のフォルダなら削除できる |
| フォルダに `rm`（`-r` なし） | エラーになる（`is a directory`）。`rm -r` なら中身ごと削除される |
| `cp` のあとに `ls` | コピー元とコピー先の2つが並ぶ。`mv` で名前を変えると、元の名前は無くなる（コピーではなく移動） |
| `mv` でファイルを別のフォルダの中へ | 元の場所からは無くなり、移動先のフォルダの中に現れる |
| `rm -i ファイル名` | `remove ファイル名?` と確認される。`y` なら削除され、`n` なら削除されずに残る |

エラーメッセージの文面は、OSによって少し違う。

## ファイルの内容を確認・書き込む

```bash
cat ファイル名                # ファイルの内容を表示する(concatenate)
cat -n ファイル名             # 行番号つきで表示する

echo 文字列                   # 文字列をターミナルに表示する
echo 文字列 > ファイル名      # 文字列をファイルに書き込む(上書き)
echo 文字列 >> ファイル名     # 文字列をファイルに追記する
```

練習: [practice/practice03.md](practice/practice03.md)

| 試すこと | 確認すること |
| --- | --- |
| `>` でもう一度書き込む | 上書きされ、前の中身は消える（最後に書いた文字列だけが残る） |
| `>>` を続けて打つ | 行が1行ずつ増えていく。`cat -n` なら、各行の先頭に行番号が付く |
| まだ無いファイル名に `>` | ファイルが新しく作られる（先に `touch` で作らなくてもよい） |
| `>` を付けない `echo 文字列` | ターミナルに表示されるだけで、ファイルは変わらない |

## ターミナルを効率よく使う

```bash
# タブ補完: パスやコマンドを途中まで入力してTabキーを押すと自動補完される
cd Doc[Tab] → cd Documents/

# 上キー: 過去に入力したコマンドを1つずつさかのぼれる
↑キー  # 1つ前のコマンドを呼び出す
↑↑キー # 2つ前のコマンドを呼び出す

# which: コマンドの実体がどのパスにあるか確認する
which python   # → /usr/bin/python など
which python3  # → /usr/local/bin/python3 など
```

> `which python` でパスが返ってこない場合は `python3` を使う

# 2. Pythonの実行

## Pythonファイルを作成して実行する

```bash
# ステップ1. ファイルを作成する
touch game.py

# ステップ2. ファイルに内容を書き込む
echo 'print("Hello, World")' > game.py

# ステップ3. ファイルの内容を確認する
cat game.py

# ステップ4. Pythonで実行する
python ./game.py
```

`./` はカレントディレクトリを意味し、「今いる場所の `game.py`」を実行する

練習: [practice/practice04.md](practice/practice04.md)

| 試すこと | 確認すること |
| --- | --- |
| `echo 'print("Hello, pygame")' > game.py` で書き換えて、もう一度実行 | `>` は上書きなので、新しいメッセージだけが表示される |
| `./` を付けずに `python game.py` | 同じように実行できる（`./` は「今いる場所」を表すので、付けても付けなくても同じ） |
| `cd ..` してから `python ./game.py` | `can't open file ... No such file or directory` というエラーになる。「今いる場所」に `game.py` が無いため |
| `cd ..` したまま `python Practice/game.py` | 今いる場所から見たパス（相対パス）なので、実行できる |
| `pwd` で確認した絶対パスで実行 | どのフォルダにいても実行できる |

# 発展(任意): テキストエディタ

`echo` では1行ずつしか書けないため、複数行を編集するにはエディタを使う

## vi (Visual Editor)

```bash
vi ファイル名      # viでファイルを開く
```

| 操作 | キー |
| --- | --- |
| 編集開始(入力モード) | `i` |
| 編集終了(コマンドモード) | `Esc` |
| 保存して終了 | `:wq` → Enter |
| 保存せずに終了 | `:q!` → Enter |

## nano

```bash
nano ファイル名    # nanoでファイルを開く
```

| 操作 | キー |
| --- | --- |
| 保存 | `Ctrl + O` → Enter |
| 終了 | `Ctrl + X` |
| 保存して終了 | `Ctrl + O` → Enter → `Ctrl + X` |

> nanoはviよりも直感的に操作できる。モードの切り替えが不要でキーボードに表示されるショートカットを見ながら使える
